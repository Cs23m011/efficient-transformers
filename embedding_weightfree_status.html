Background — What Weight-Free Export Is

Standard ONNX export loads all model weights into CPU RAM, embeds them as tensor initializers in the ONNX protobuf, and writes a large file to disk. For a 335M-parameter model (bge-large) this means ~1.3 GB in RAM just to hold the weights before export begins.

Weight-free export avoids this entirely:

  1. A meta-device skeleton model is built — correct architecture, zero bytes of weight data.
  2. torch.onnx.export traces the skeleton symbolically. The ONNX graph captures operators and shapes but contains no tensor values.
  3. A sidecar weight_spec.json maps every ONNX input name to its key in the original safetensors checkpoint file.
  4. At ORT inference / AI100 compile time, weights are streamed directly from the checkpoint — never duplicated in RAM.

                    ─────────────                 ────────────────
CPU RAM during export:   ~1.3 GB (bge-large)       ~0.05 GB (meta skeleton only)
ONNX file size:          ~640 MB (embedded weights) ~2 MB   (graph only)
Checkpoint read:         once to RAM, then to ONNX  streamed at inference time

Issues Found & Fixes Applied

Issue 1 — Non-persistent buffer position_ids causes FakeTensorDeviceMismatchError

Symptom: Export crashes immediately during torch.export.export with:
FakeTensorDeviceMismatchError: tensor on meta device, position_ids on CPU

Root cause: BertEmbeddings registers position_ids and token_type_ids as non-persistent buffers (register_buffer(..., persistent=False)). accelerate.init_empty_weights() only moves parameters and persistent buffers to the meta device. Non-persistent ones stay on CPU. When the dynamo exporter traces the meta model it sees CPU tensors alongside meta tensors and raises a device mismatch error.

Fix: QEffBertEmbeddings in QEfficient/transformers/models/bert/modeling_bert.py — removes both buffers entirely from __init__ and recreates them on-the-fly inside forward() from input_ids.device. This works for all export modes:

class QEffBertEmbeddings(BertEmbeddings):
    def __init__(self, config):
        super().__init__(config)
        for name in ("position_ids", "token_type_ids"):
            self._buffers.pop(name, None)          # remove buffer entirely
            self._non_persistent_buffers_set.discard(name)

    def forward(self, input_ids=None, ...):
        device = input_ids.device                  # picks up meta / cpu / cuda
        position_ids = torch.arange(..., device=device).unsqueeze(0)
        token_type_ids = torch.zeros(input_shape, dtype=torch.long, device=device)
        return super().forward(...)

FIXED — applies to BERT, RoBERTa, XLM-RoBERTa families via QEffBertModel / QEffRobertaModel / QEffXLMRobertaModel.

Issue 2 — PooledModel wrapper not re-applied on meta model → pooling op missing from ONNX graph

Symptom: Export completes but ORT output shape is (1, seq_len, 768) instead of (1, 768). Comparison with HF baseline fails with shape mismatch: MAD 0.136 >> threshold 1e-5.

Root cause: When the user builds QEFFAutoModel(model, pooling="cls"), the backbone is wrapped in PooledModel(backbone, cls_pooling). The weight-free path internally rebuilds a fresh meta model via _build_meta_qeff_model(), but this function creates the meta QEFFAutoModel without the pooling= kwarg. The meta model is a bare backbone. When exported, the ONNX graph ends at last_hidden_state [B, seq_len, hidden] with no CLS pooling node.

Fix: After building the meta QEFFAutoModel, detect and replicate the PooledModel wrapping:

# in QEfficient/exporter/weight_free.py — _build_meta_qeff_model()
from QEfficient.transformers.embeddings.embedding_utils import PooledModel
from QEfficient.transformers.models.pytorch_transforms import PoolingTransform

if isinstance(qeff_model.model, PooledModel):
    meta_qeff_model.model, _ = PoolingTransform.apply(
        meta_qeff_model.model, qeff_model.model.pooling_fn
    )

FIXED

Issue 3 — base_model. prefix mismatch between ONNX initializer names and checkpoint keys

Symptom: After fix 2, export crashes on onnx_program.save():
SerdeError: Cannot copy out of meta tensor — base_model.embeddings.word_embeddings.weight

Root cause: PooledModel stores the backbone as self.base_model. PyTorch's named_parameters() therefore prefixes every parameter name with base_model.. The ONNX graph initializer names pick up the same prefix. The safetensors checkpoint was saved from the raw BertModel and uses bare keys (e.g. embeddings.word_embeddings.weight). The weight spec builder does a direct dict lookup — the prefixed ONNX name is not found → the parameter is not promoted to an ONNX input → it stays as an initializer with a meta-tensor value → serialisation crashes.

Fix: One-level prefix-strip fallback in _promote_initializers_and_build_spec():

checkpoint_file = checkpoint_index.get(location_key)
if checkpoint_file is None and "." in location_key:          # fallback only if direct lookup fails
    stripped_key = location_key.split(".", 1)[1]              # strip "base_model."
    checkpoint_file = checkpoint_index.get(stripped_key)
    if checkpoint_file is not None:
        location_key = stripped_key

This is a safe fallback — it only runs when the direct lookup fails, so existing LLM models (Llama, GPT-OSS, GLM-MoE) whose checkpoint keys match their ONNX names directly are completely unaffected.

FIXED
